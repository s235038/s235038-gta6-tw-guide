## 新增或修訂一篇攻略

1. 先定一個玩家問題和適用情境。命名穩定的英文 slug，避免發佈後因更換標題而改網址。
2. 在存證清單記下來源標題、網址、發布日期、查核日期、可信程度，以及各自支持的句子。持續維護的官方支援頁若無公開發佈日期，記為「未標日期」。
3. 以 Markdown 新增或更新文章。保留原始發布日，有實質更正再更新最後更新日。選擇分類，填寫摘要、標籤、查證狀態、相關文章和劇透標記。[文章範本](article-template.md)
4. 把結論放在第一段。使用看得見的介面名稱、起點、前置條件與完成判斷。媒體有實測就明確署名，記錄平台或版本，以及編輯部是否已複驗。
5. 執行 `npm run content:check`、`npm run check` 和 `npm run build`。用手機寬度打開首頁和文章，操作防劇透、檢查站內連結和來源。確認標題、摘要、分享預覽與玩家要查的問題一致，再納入下一次發佈。

### 來源驗證清單

- [ ] 平台、上市時間、版本與語言有 Rockstar 或台灣區官方平台頁佐證。各地區、實體與數位差異單獨標明。
- [ ] 玩法和任務有可追溯的第一手實測。若涉及解鎖、金額、座標或分歧結果，再比對另一份獨立資料或在同條件重現。
- [ ] 官方已確認、媒體實測、玩家提供尚待交叉驗證、尚未確認依主張分別標示。一篇含多種證據時，在相關小節也加上個別說明。
- [ ] 玩家回報只進待辦，保留必要的章節、版本與可重現步驟，避免收集玩家真名、可識別帳號及私人資料。
- [ ] 確認引用的是 GTA VI。檢查名稱、平台、遊戲版本和情境皆與來源對得上。
- [ ] 內容採獨立撰寫與原創圖形。連到來源頁供讀者核對，僅摘取所需的事實。
- [ ] 劇情答案、後續地區及任務揭露有正確的劇透標記。標題、摘要和分享卡同樣檢查。

## 定期複查與攻略待辦

每週執行 `npm run content:check -- --report-stale`。依報告打開原始資料，核對上市狀態、遊戲版本、地區、商店標價和玩法適用條件。若只是確認資料仍有效，更新 `sources[].checked`。有實質內容變動才更新 `updated`。來源連結由編輯時確認是否打得開及仍支持原文。站內文章引用和欄位由內容檢查及 Astro 建置驗證。

收到重複的搜尋或卡關回報時，新增待辦並寫明玩家要解決的問題、可重現情境與缺少的證據。依優先序挑一個可驗證的問題處理。發布後把文章連結和狀態補進待辦。[攻略待辦](../CONTENT_BACKLOG.md)

## 流量與使用驗證

| 指標 | 免費量測方式 | 解讀 |
| --- | --- | --- |
| 收錄狀態 | Google Search Console 的網頁索引及網址審查 | 先核對首頁和首批文章能被 Google 擷取，必要時排查 sitemap、canonical 或 404。 |
| 搜尋曝光、點擊、CTR | Search Console 搜尋成效，依查詢與到達頁分組 | 優先看「繁中、上市、版本、新手、卡關」各詞組。曝光過少時先保留資料，避免從單日 CTR 判斷方向。 |
| Threads 有效互動 | 手工記錄每篇可見的瀏覽、回覆、轉發與引用。帳號有連結點擊數時一併記下 | 把重複問到且能具體定位的問題加入待辦。分開記錄不同貼文與觀察時間。 |
| 手機任務成功 | 邀請 3–5 人完成搜尋、開文與收藏。只記成功筆數、耗時區間及碰到的障礙 | 先修一再重現的操作障礙，再追加新功能。 |
| 回訪意願 | 自願試用者隔天回報是否能重新找到先前收藏 | 以匿名彙總作為早期訊號。本機收藏目前只有讀者自己能看到。 |

公開後，在 Search Console 建立網站完整子路徑的網址前置字元資源，依 Google 畫面選擇可行的驗證方式，再提交該站的 `sitemap.xml`。GitHub Pages 站點可先走 HTML 檔案驗證。用私有試算表或本機 CSV 紀錄彙總資料即可，網站維持無第三方追蹤腳本。
